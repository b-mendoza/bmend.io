# Architecture

## Platform and Runtime

- **Target platform**: Cloudflare Workers
- **Server framework**: TanStack Start, running on the default Start server entry (`@tanstack/react-start/server-entry`, configured as `main` in `wrangler.jsonc`)
- **Dev/preview runtime**: Vite with the Cloudflare Vite plugin, running against workerd for both `pnpm run dev` and `pnpm run start` (preview)
- **Build output**: `pnpm run build` produces `dist/client` (static/browser assets) and `dist/server` (the Worker bundle)
- **Rendering**: Server-side rendering with client hydration is now enabled as part of this migration (the prior Remix baseline shipped no hydration bundle)

## Routing and Server Configuration

### Routing

- **File-based routing**: Routes live in `app/routes/`, with a custom root route/shell defined in `app/routes/__root.tsx` (`shellComponent` renders the `<html>`/`<head>`/`<body>` document)
- **Route tree**: Auto-generated by the TanStack Start Vite plugin into `~/routeTree.gen` from the routes in `app/routes/`; this file is generated at build/dev time and should not be hand-edited
- **Static assets**: Served from `./public`; hashed build assets are served from `/assets/*`

## Application Structure

- **Path alias**: `~/*` maps to `./app/*` (configured in tsconfig.json)
- **Component organization**: Components use folder structure with `*.component.tsx` + `index.ts` pattern
  - Example: `app/components/button/button.component.tsx` + `app/components/button/index.ts`
- **Server-only code**: Files ending with `.server.ts` contain server-only logic (models, utilities) and are kept out of the client bundle
- **Server function boundary**: Route loaders call server functions in `app/functions/*.ts` (built with `createServerFn`), which dynamically import the corresponding `.server.ts` model to preserve the client/server boundary
- **Data models**: Located in `app/models/*.server.ts` - contain data fetching functions
  - Current models use in-memory data with comments indicating future database/CMS integration
- **CSS imports**: Stylesheets are imported with Vite's `?url` suffix (e.g. `import globalStyles from '~/styles/global.styles.css?url'`) and registered as `<link>` tags in the root route's `head()`

## Environment and Context

- Server-only code (models, utilities) lives in `.server.ts` files; no Cloudflare environment bindings are currently defined for this app
